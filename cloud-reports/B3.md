## How the project builds and runs

There is no README. This is what I worked out from the code.

- **Install:** `uv sync` (reads `pyproject.toml` + `uv.lock`; Python ≥ 3.12). Dev tools (pytest, httpx) are in the `dev` group that `uv sync` installs by default.
- **Database:** `data/intel.db` (gitignored, not in the repo). The root-level `intel.db` is an empty 0-byte file that nothing uses.
  - `uv run python -m seed.seed_db` creates the schema (`schema.sql`) and loads the base layer: `curated_entities` + `expansion_political`, `_financial`, `_hollywood`, `_inner_circle` (159 entities, 323 relationships, 140 sources).
  - Every other layer is added one at a time: `uv run python -m seed.add_expansion seed.expansion_<name>`. The order isn't written down anywhere. Going by source-ID order, it is: russia, china, saudi, uk, israel, bohemian_grove, france, germany, latin_america, uap_disclosure, wef. In that order no relationships are skipped.
  - `seed/inner_circle_enablers.py` is a draft layer that isn't wired in. It uses `NEW_*` variable names and source IDs 116–140, which clash with `expansion_inner_circle`.
- **Signals:** `uv run python signal_collector.py` polls RSS, the Federal Register, SEC EDGAR and OFAC, and writes to `data/intel.db`. Its docstring says it's meant to run from cron. I did not run it.
- **Static export (the actual site):** `uv run python export_static.py` reads `data/intel.db` and **overwrites** `static/data/*.json` (9 files, including `geo-*.json` via `geo_enrich.py`).
- **Site:** `static/` is a self-contained static site (vanilla JS + SVG) that reads `static/data/*.json`. Serve `static/` as the web root, e.g. `cd static && python3 -m http.server`. The geo files are for the external "WorldView" globe.
- **Dev server:** `./serve.sh` seeds the base layer if `data/intel.db` is missing, then runs `uvicorn server.app:app` on port 8800 with `--reload`. It serves the FastAPI JSON API under `/api/...` and the site. The frontend does **not** call the API; it only reads the static JSON.
- **Tests (new):** `uv run pytest`. See "Safety net".
- **Deploy:** there's no deploy config in the repo. `export_static.py`'s docstring says the output goes to GitHub Pages. Nothing was deployed.

## Safety net

`uv run pytest` runs `tests/test_smoke.py`. Nothing in it touches `data/intel.db` or `static/data/`. Everything is built in temp dirs.

- `test_export_from_seeds`: seeds a temp DB from all of `seed/`, runs `export_static.main()` into a temp dir, and checks all 9 JSON files exist and parse, there are ≥250 entities and ≥600 edges, the stats match the graph, and tiers are valid.
- `test_committed_static_data_consistent`: the served `static/data/` has every file, the stats match the graph, no edge points at a missing entity, tiers are valid, and every `photo_url` exists on disk.
- `test_index_assets_exist`: every `src`/`href` in `index.html` exists.
- `test_api_and_site_serve`: FastAPI `TestClient` against the seeded DB. `/`, `/css/style.css`, `/js/app.js`, `/data/graph.json` and `/static/...` return 200; the stats, search and graph endpoints return data.
- `test_site_in_headless_browser`: runs `tests/browser_smoke.js` (Node + Playwright). It serves `static/`, loads it in headless Chromium, and fails on any console error, page error or failed request, on fewer than 100 rendered nodes, on a missing initial breadcrumb, or if clicking a node doesn't enter ego mode. It **skips** if `node` or the `playwright` npm package isn't installed. On a laptop that needs `npm i -g playwright && npx playwright install chromium`.

I checked that the tests catch real breakage:
- Reverting the `app.py` fix fails `test_api_and_site_serve` (`AssertionError: /css/style.css`).
- Stopping the export from writing `graph.json` fails `test_export_from_seeds`.
- Restoring the old `app.js` fails the browser check with the original `ReferenceError`.
